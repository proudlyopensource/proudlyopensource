# Security Policy

## Supported Versions

This project is in early development. Security updates will be applied to the latest version on the `main` branch. Formal version support will be documented as releases are published.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

To report a vulnerability privately, please use one of the following methods (maintainer to establish as needed):

- GitHub Private Vulnerability Reporting (if enabled for this repository)
- A private contact channel established by the maintainers

## What to Include in a Report

When reporting a vulnerability, please include:

- A description of the vulnerability and its potential impact
- Steps to reproduce or a proof of concept
- Affected versions/branches
- Any suggested mitigations if available

## Our Response Process

- We will acknowledge your report as soon as possible.
- We will investigate and keep you informed of progress.
- We will work with you on coordinated disclosure once a fix is available.
- We will credit reporters as appropriate, unless you prefer to remain anonymous.

## Important Notes

- Do **not** request secrets, passwords, or production credentials in issues or pull requests.
- Do not disclose the vulnerability publicly before coordinated remediation.
- Removing a secret from the latest commit does not remove it from Git history; if a secret was committed, it must be rotated and history cleanup handled separately.
